免费节点采集器 · 使用说明
════════════════════════════════════

一、线上网页（已发布）
   https://bob0098.github.io/nodes/
   手机、电脑直接打开就能用，不用装任何东西。

   页面是纯静态单文件：所有数据在构建时整份内嵌进 index.html，
   打开即显示，不发任何网络请求，断网也能打开。

二、关于「自动更新」——实际是怎么跑的
   1) 页面上的 14 条订阅链接，都是各仓库长期自动更新的地址。
      仓库那边每天/每几小时更新一次，客户端订阅后每次点「更新」
      自动拿最新节点。这一层不需要任何定时任务，天然就是每天更新。

   2) 页面上显示的「条节点」和可连率，是最近一次采集的结果。
      采集由 GitHub Actions 每 3 小时跑一次，把数据整份写进 index.html。
      页头会直接写「数据更新于 11-24 17:54」；超过 6 小时没刷新，
      那行会标红提示「已 N 小时未刷新」——看到红色就说明 Actions 卡住了。

   3) 所以你不需要电脑一直开着，也不用配定时任务。
      GitHub 队列会有延迟，实际间隔常在 3 小时以上；
      想立刻刷新就手动触发：Actions → 节点数据更新 → Run workflow。

三、每张卡片上的数字怎么来的
   · 条节点      该订阅文件里的真实条目数（Clash 数 proxies，sing-box 数 outbounds，其余数 URI 行）
   · 可连率      从该源里抽最多 24 个节点，在采集机上做 TCP 握手，通的占比
   · 源更新于    该仓库最后一次提交距今多久（GitHub commits API）；超过 30 小时标「可能已停更」
   · 近期不稳    连续 2 轮采集可连率都低于 30%
   · 国内常不通  源站在国内直连经常打不开，得先有可用代理才能订阅

   注意：测量点是 GitHub 的美国机房，国内直连的百分比会明显偏低，
   这个数字只用来排序，不代表你自己网络下的实际体验。
   只测 TCP 类节点；hy2 / tuic 走 UDP，没法用 TCP 探，不计入分母。

四、本地重新生成（可选）
   python3 collector.py            联网采集并重建页面
   python3 collector.py --cache    用本地缓存重建（不联网，快）
   python3 collector.py --render   只按 data/nodes.json 重渲染页面，不联网

   产出：
   · index.html                 网页（数据已内嵌，离线也能打开）
   · data/nodes.json            结构化数据（供脚本/监控读，页面本身不依赖）
   · data/status.json           每条源的 HTTP 状态码与耗时
   · data/health.json           连通率历史与内容指纹（只在 CI 里写，本地不写）
   · og.png                     分享卡片图（1200x630，静态，不随采集变）
   · 订阅 全部节点 base64.txt    全量去重清单，可直接导入 v2rayNG / Shadowrocket
   · 订阅 全部节点 明文.txt      同上，明文 URI 列表

五、发布到自己的 GitHub（可选，想换成自己的域名时用）
   1. 新建仓库，把本目录全部文件 push 上去
   2. Settings → Actions → General → Workflow permissions 选 Read and write
   3. 内置 .github/workflows/daily.yml，每 3 小时（cron 17 */3 * * *）自动采集并提交
      带 2 小时新鲜度闸门：cron 迟到导致重复触发时直接跳过
   4. 开启 GitHub Pages，Source 选 main 分支根目录（/），得到自己的网址
   5. 换域名的话，还要改 template.html 里写死的 canonical / og:url / og:image 三处

六、采集规则
   · 14 个源，并发拉取（Clash 5 条、V2Ray 5 条、sing-box 4 条）
   · 去重键 = 服务器地址 host:port（vmess 会解 base64 取真实地址）
   · 过滤非节点行（如 https://IP:443）和非法协议
   · 排序分 = 可连率 × 条数，即「预计可用节点数」；国内常不通的源固定沉底
   · 采集量低于上次的 60% 视为不完整，直接放弃本次结果，保留旧数据

七、注意
   · 免费节点随时失效，一条不好用就换下一条
   · 全程只访问公开仓库和公开订阅地址，不涉及任何账号
   · 仓库里那两份「订阅 全部节点」txt 是全量导出，不保证可用；页面链接仍是各仓库原样地址
