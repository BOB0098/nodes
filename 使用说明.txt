一、线上网页（已发布）
   https://a1ca854d62b3e7bcd.app.workbuddy.host/?sharecode=K5H5HTZ3KG
   手机、电脑直接打开就能用，不用装任何东西。

二、关于「每天自动更新」——实际情况
   1) 页面上那 14 条订阅链接，都是各仓库长期自动更新的地址。
      仓库那边每天/每几小时更新一次，客户端订阅后每次点「更新」
      自动拿最新节点。这一层不需要任何定时任务，天然就是每天更新。

   2) 页面上显示的「条节点」数字，是打开页面的那一刻现拉的：
      浏览器直接去各仓库读取订阅内容并重新计数，8 条能读到最新值
      （显示为蓝色数字）；剩下 3 条是尔毛子的订阅，对方服务器没开
      跨站读取权限，浏览器拿不到，显示最近一次采集值（灰色数字）。

   3) 所以你不需要电脑一直开着，也不需要配什么定时任务。
      每天打开网页，看到的条数就是当天最新的。

三、本地重新生成（可选）
   python3 collector.py            联网采集并重建页面
   python3 collector.py --cache    用本地缓存重建（不联网，快）
   python3 collector.py --render   只按 data/nodes.json 重渲染页面，不联网

   产出：
   · index.html                 网页（数据已内嵌，离线也能打开）
   · data/nodes.json            结构化数据
   · 订阅 全部节点 base64.txt    可直接导入 v2rayNG / Shadowrocket
   · 订阅 全部节点 明文.txt      明文 URI 列表

四、发布到自己的 GitHub（可选，想让链接换成自己的域名时用）
   1. 新建仓库，把本目录全部文件 push 上去
   2. Settings → Actions → General → Workflow permissions 选 Read and write
   3. 内置 .github/workflows/daily.yml，每 3 小时（cron 17 */3 * * *）自动采集并提交
   4. 开启 GitHub Pages（gh-pages 分支），得到自己的网址
   注意：GitHub 队列会延迟，页面写「约 3 小时更新」，并显示距下次采集的倒计时；
   倒计时只是按 cron 推算，排队时会在胶囊里改口说「队列可能堵着」。想立刻刷新就手动 Run workflow。

五、采集规则
   · 14 个源，并发拉取（每类约 5 条，只收一天内更新过、且能带来独有节点的源）
   · 去重键 = 服务器地址 host:port（vmess 会解 base64 取真实地址）
   · 过滤非节点行（如 https://IP:443）和非法协议

六、注意
   · 免费节点随时失效，一条不好用就换下一条
   · 全程只访问公开仓库和公开订阅地址，不涉及任何账号
