# P17：评分与检测口径

> 2026-11-25。这一篇只讲一件事：**为什么把 40 分的「TCP 可连率」拆掉**，
> 以及改完之后哪些源的位置变了。
> 数据取自 11-25 07:50 那一轮（`data/sources_stats.json` + `data/nodecheck.json`）。

## 1. 改之前的三个数

同一批源、同一轮，三个口径给出三个结论：

| 口径 | anaer | radarhub | 谁排第一 |
|---|---:|---:|---|
| TCP 抽样可连 | 67% | 100% | — |
| 真实握手可用 | **0/90** | **85/90** | — |
| 源评分（旧） | **A 87.0** | B 74.8 | anaer |

`anaer` 1,770 条节点，端口 67% 能连，真握手一条都没通，评分 87 分 A 级，
在 Clash 分组里排第一。`radarhub` 真握手 94%，排在它后面。

排序函数只有一行：

```python
# 旧 collector.py
return ok / total * n        # TCP 可连率 × 节点数
```

真实握手的结果（`rok` / `rtest`）在同一个函数上方已经取到了，只用于显示。
**页面拿最不可靠的口径做排序，再拿评分徽章给它背书。**

## 2. 新公式

| 维度 | 满分 | 计算方式 |
|---|---:|---|
| **真实可用率** | 32 | `32 × min(1, 率/0.7)^0.8`，70% 封顶 |
| **真实可用条数** | 10 | `10 × log(1+可用数) / log(801)`，800 条封顶 |
| 样本置信 | 4 | `4 × min(1, 样本/60)` |
| 独立新增 | 10 | 对数刻度，1,500 条封顶 |
| 独立率 | 6 | 独立新增 / 原始解析，50% 封顶 |
| 新鲜度 | 10 | 2 小时内满分，7 天以上 0 |
| 稳定性 | 14 | 连败 10（0/1/2/≥3 轮 → 10/7/3/0）+ 波动 4 |
| TCP 可连率 | 8 | 辅助；**无真实握手样本时此维度上限为 27.2，TCP 抽样缺失记 13.6** |
| 合规/类型 | 6 | 许可证 3 + 来源类型 3 |

**三条上限**（在 `annotate()` 里，紧跟等级判定）：

| 条件 | 上限 | 理由 |
|---|---|---|
| 没有真实握手数据 | 最高 B | 没测过不该和测了很好同级 |
| 样本 < 20 条 | 最高 A | 10 条里通 9 条说明不了什么 |
| 连续隔离 | 强制 D | 原有逻辑，不变 |

为什么是 70% 封顶：免费节点池真实可用率中位 34%、最好的源 94%，
70% 是「很好」的锚点。拿 100% 当满分会让所有源都挤在及格线附近，
这也是旧公式 40 分给 TCP 后五档只用得到三档（S1/A9/B5/C0/D0）的原因。

为什么 TCP 还留 8 分：它回答的是另一个问题——「这个源还活着吗」。
采集失败时它是唯一还能拿到的信号。但它不再能决定排名。

为什么无真实数据时 TCP 上限抬到 27.2（8 + 0.6×32）：新源第一轮没有握手数据，
直接给 0 分会把好源判死。补偿 60% 而不是 100%，是因为端口证据本来就比握手证据弱。
这里的 27.2 是动态维度上限，不是固定赠分：有 `alive_pct` 时按 TCP 可连率折算，
70% 即达上限；如果 TCP 本身也未抽样，则记该上限的一半 13.6。只要真实握手样本数大于 0，
TCP 维度上限立即回到 8；TCP 抽样缺失时相应记 4。

## 3. 改完之后的位移

| v2ray-configs | 0/90 | A 87.3 | **C 54.6** | ↓↓ |
| ALIILAPRO | 7/90 | A 89.5 | **C 64.8** | ↓↓ |
| 尔毛子·V2Ray | 24/90 | **S 91.7** | B 73.2 | ↓ |
| Andrejewild | 0/18 | A 88.8 | **D 46.2** | ↓↓ |
| v2rayfree | 0/4 | A 81.0 | **D 39.2** | ↓↓ 样本仅 4 条 |
| radarhub | 85/90 | B 74.8 | B 79.2 | 分数升，但独立性只有 6 条，仍 B |
| Barabama | 48/90 | A 86.2 | A 80.5 | 微降 |

等级分布从 **S1 / A9 / B5 / C0 / D0** 变成 **S0 / A2 / B6 / C5 / D2**，五档全部用到。

两个反常但合理的例子：

- `awesome-vpn` 只有 21 条样本，仍拿 A。它不是大源，但 17/21 真通过、
  独立新增 21 条、16 小时前更新过。21 条刚过 20 的门槛，所以 A 允许；
  如果只抽到 10 条，上限会压到 A 以下（这条规则在 `cap_grade()` 里）。
- `radarhub` 真实可用 94%，却只有 B 79.2。它的 495 条里 489 条与其他源重复，
  独立新增只有 6 条——独立新增那一项只拿到 0.9/10。这是刻意的：
  一个全是转载的源，再可信也不增加用户能拿到的节点数。

## 4. 排序规则

```python
# 新 collector.py
def _rank_real(item, counts, probes, real):
    if rtest:
        return float(rok), 1        # 真实可用条数，绝对值
    return 0.3 * tcp_rate * n, 0    # 没有真实数据：按端口打三折，排在后面
```

排序键：`(国内直连不通, 已隔离, 无真实数据, -真实可用条数, 优先级)`。

试过两种更"聪明"的写法，都被数据否掉了：

1. `可用率 × 条数`：anaer 0% × 1770 = 0，没问题；但 `v2ray-configs` 0%
   × 3884 = 0 也一样，两者并列，没有区分度。
2. 向 25% 先验收缩：`0 + 0.25 × 1770 × (1-conf) = 110`，
   0 可用的源靠条数拿到 110 分的保底，仍排在 48/90 的源前面——
   与「按可用条数排」这个口径自相矛盾。

最后选了最笨的：**就是可用条数本身**。卡片上写着「真实可用 48/90」，
用户一眼能看出它为什么在这个位置。可解释比精巧重要。

`cnbad`（国内直连不通）仍然优先于排序分：这类源复制出来也打不开，
放在前面只会浪费用户的时间。卡片上有「国内常不通」的标记，不是静默沉底。

## 5. 失败分类

以前 `probe()` 只读 `%{http_code}`，失败一律记 `HTTP 000`——
最新一轮 609 条失败**全是这一个标签**。它至少混了四种情况：

| curl 退出码 | 分类 | 含义 |
|---:|---|---|
| 6 | `dns` | 域名解析失败 |
| 7 | `tcp` | 连接被拒或不可达 |
| 28 | `timeout` | 超时 |
| 35 | `tls` | TLS 握手失败 |
| 52 / 56 / 60 | `empty` / `recv` / `cert` | 空响应 / 接收失败 / 证书问题 |
| 5 | `proxy` | 本地 mihomo 没起来 |
| 其它 | `other` | 保留原始异常类型 |

连上了但目标站返回非 204 的，记 `http:<code>`——这类不能算节点死，
同一条链路换个目标可能就通，归到「目标站异常」而不是「节点不可用」。

`nodecheck.json` 的 `summary.err_classes` 按阶段计数：

```json
"err_classes": {"<阶段>": <条数>, ...}
```

阶段名取自上面的表（`dns` / `tcp` / `tls` / `timeout` / `http` / ...），
按条数降序。有了这个，下一轮才能回答「这个源掉了 20 个点，
是它发了坏节点，还是机房在掐这类流量」。
本轮跑在旧代码上，还没有这份分布；下一轮才有真实数字。

## 6. 兼容与迁移

- `SCORE_VERSION = 2` 写在 `score.py` 顶部。`source_history.json` 里的旧条目
  没有 `real_pct`，`_d_stable()` 会退回 `alive_pct` 算波动，不会崩。
- **跨版本的历史不做绝对分比较**。旧 87 分和新 51 分不是同一个尺子，
  趋势图只连同一版本内的点。
- `data/*.json` 加 `schema: 2`。`check_consistency.py` 读这个字段，
  遇到旧格式只警告不失败。
- 页面卡片字段新增 `rank_real` / `rank_has_real`，旧字段全部保留，
  第三方按旧结构读不会断。

## 8. 还剩什么

- **评分仍滞后一轮**：采集时评分读的是上一轮 `node_scores.json`。
  同一轮里「页面的真实握手」和「该源的评分」可能来自不同轮次。
  P20 用 manifest 统一。
- **`Pawdroid` 这类 0 样本源**：现在最高 B、实际 C。样本来了会自动修正，
  但页面应该显示「未抽样」而不是让它看起来像「测了不行」——P21 处理文案。
- **`best` 订阅的分组条件仍然写死 ≥65 分**。新公式下 65 分对应的真实可用率
  比旧公式高得多，这条阈值要在一两轮数据后重估。
