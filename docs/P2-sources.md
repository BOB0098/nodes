# P2：来源扩充、审核管线与自动发现

> 日期：2026-11-24　基线：P1 完成态（节点库 8,455 条）
> 配套：`sources.yaml`（登记表）、`screen.py`（审核）、`discover.py`（发现）、
> `data/screening.json`（原始数据）、`docs/P2-screening.md`（自动生成明细）

## 1. 解决的两个结构性问题

**① 两张清单互相打架。** 旧的 `collector.py` 里 `GROUPS`（14 张页面卡片）与
`SOURCES`（9 个采集项）是两张独立维护的表：7 张卡片不参与节点库，2 个源采了却不展示。
页面写 ALIILAPRO 有 4,843 条、库里只有 2,835 条，两个数谁也解释不了谁。

现在合并为 `sources.yaml`：**一张卡片 = 一个源**，`collector.py` 只认这一份。
启动时做结构校验（id/name 唯一、group 存在、type/format 枚举、启用项必须有卡片文案），
坏清单直接报错，不会带着问题跑一轮。

**② 新源没有准入标准。** 现在有 `screen.py`：试采集（限 12 MB）→ 解析（与入库同一套
`nodes_parse`）→ 去重（全参数指纹）→ 真实检测（抽样 24 个 TCP 握手）。规则写死在代码里。

## 2. 登记表字段

| 字段 | 含义 |
|---|---|
| `id` | 稳定标识，换 URL 不改它（健康记录、统计按 id 归档） |
| `url` / `mirrors` | 给用户复制的原版地址 / 仅采集用的备用地址 |
| `type` | `original`（源作者产数据）或 `aggregator`（聚合他人） |
| `format` | `clash` / `v2ray-base64` / `v2ray-plain` / `singbox-json` |
| `license` | SPDX；`null` = 仓库未声明（合规风险，需人工确认） |
| `priority` | 同组排序权重 |
| `enabled` | 是否采集与展示。**新源必须审核 + 人工置 true** |
| `note` | 人工判断：迁移、重合、风险，附审核数据 |

动态字段（最近抓取、各阶段条数、失败次数、最近错误、质量评分）由 `collector.py`
每轮写入 `data/sources_stats.json`，不放进 YAML——否则每轮采集都会产生大段 diff。

## 3. 判定口径（这一版改过一次，原因重要）

第一版用「抽样可连率 ≥30%」当硬门槛。实际跑完发现这个指标**不稳定**：
同一个 ALIILAPRO 在一天内测出 42% 和 8%，取决于出口网络和时段。用它做硬门槛，
好源会被随机误杀。

现在的口径是**预计可用新增 = 真正新增 × 可连率**：

| 门槛 | 值 | 理由 |
|---|---|---|
| HTTP | 200 | 源必须可达 |
| 解析条数 | ≥20 | 撑不起一张卡 |
| 独立新增占比 | ≥10% | 低于此说明是别的源的下游 |
| 预计可用新增 | ≥250 条（<600 记 watch） | 反映"能给用户多带来几个能用的节点" |
| 归档 / 停更 | 排除 | 30 天内无提交即视为停更 |

### 四个必须记住的结论

**① 体积大 ≠ 节点多。** `xiaoji235/airport-free` 的 clash 文件 3.7 MB，实际只有
**21 个内联节点**；其余 6,690 个 `name:` 全是 ACL4SSR 的**规则集**。同理
`rtwo2/FastNodes` 的 `everything.txt` 恰好 52,428,780 字节——GitHub 单文件 50 MB
截断的结果，内容本身就不完整。按文件大小评估来源会系统性高估。

**② 聚合源之间存在"包含关系"，地址级比对查不出来。**
`NoMoreWalls` 按地址比对显示"独立新增 73 条、可连 46%"，看着能加。
但用指纹复核：它的 277 个唯一指纹**全部**已被「尔毛子·V2Ray」包含（277/277）——
尔毛子本来就把 NoMoreWalls 当上游。真实新增 = 0。

同一方法复核对真正有价值的两个候选：

| 候选 | 唯一指纹 | 已被现有全源覆盖 | 真正新增 | 占比 |
|---|---:|---:|---:|---:|
| MatinGhanbari | 3,848 | 2,084 | **1,764** | 46% |
| TGParse | 4,642 | 640 | 4,002 | 86% |
| NoMoreWalls | 277 | 277 | **0** | 0% |

这就是为什么去重必须用全参数指纹，而不是 host:port，也不是地址。

**③ 「量」与「可用」在这个领域是负相关的。**

| 类型 | 代表 | 解析量 | 抽样可连 |
|---|---|---:|---:|
| 未检测的铺量聚合 | TGParse / V2rayCollector | 1,547–8,189 | 4–12% |
| 有自测的社区项目 | NoMoreWalls | 283 | 46% |
| 在册"精选"型 | Pawdroid / 尔毛子可连 | 十几–几百 | 42–100% |

接入 8,189 条、92% 是死节点的源，不是扩容，是把噪声搬进库里。

**④ 改名与派生很普遍。** `aiboboxx/v2rayfree` 301 到 `free-nodes/v2rayfree`，
两仓库 README(37,608 B) 与 sub(5,060 B) **字节数完全一致**——同一次改名，已在册地址更新。
`chengaopan/AutoMergePublicNodes` 282 条里 228 条（83%）与 NoMoreWalls 指纹相同，
`fetch.py`、LICENSE 字节数也一致，是派生项目。

## 6. 自动发现

`discover.py` 用 4 组检索式（Clash 订阅 / v2ray 免费节点 / sing-box 配置 / 中文"免费节点 订阅"）
搜 GitHub，条件：星数 ≥30、14 天内推送、未归档、不在册、不在队列；命中后读仓库树挑出
真实数据文件，避免把"只有 README"的项目塞进队列。

**边界（任务书 §4 硬要求）**：

- 只写 `data/candidates.json`，**永不**修改 `sources.yaml`；
- 候选仍需 `screen.py` 四关 + 人工置 `enabled: true`；
- 已在册 / 已在队列的仓库不重复进队；
- 独立工作流每周一跑（`.github/workflows/discover.yml`），与采集解耦。

## 6.5 自动发现的实跑结果

四组检索式（星数 ≥30、14 天内推送）共命中 483 个仓库，取各组前 10 深挖，经文件名过滤 +
**内容嗅探**（必须成批 URI / Clash `proxies:` 段 / 整体 base64）后剩 2 个：

| 仓库 | 星数 | 解析 | 结论 |
|---|---:|---:|---|
| free-nodes/clashfree | 17,423 | 0 | 全库 18 个节点都指向 `192.0.2.1:1`（RFC5737 文档保留地址），是占位数据；解析器按保留地址过滤掉，判定正确 |
| igareck/vpn-configs-for-russia | 9,807 | 767 | 真正新增 165 条、可连 38%，预计可用 63 条，未达 250 门槛 |

首轮嗅探还捞出过 `zsh-users/zsh`（`subst.c` 命中 "sub"）和 `v2rayA/v2rayA`
（`.nfpm.yaml` 打包描述）——这正是「文件名匹配」不可靠的证据，所以内容嗅探是必需的。

**结论：自动发现不产生"更多更好"，它产生的是"更多需要人工判断"。** 这正是任务书要求
「不得自动加入订阅」的原因。

## 7. 已知限制（不掩盖）

1. **`screen.py` 的重叠是地址近似。** 库内已脱敏（无 uri），CI 里算不了指纹。
   本轮用指纹复核补上了这一层（见 §4②），但那是**离线一次性核对**，没有进 CI。
   后续可把指纹摘要（只有 hash，不含凭据）落盘到 `data/`，让在线审核也能精确去重。
2. **TCP 通 ≠ 代理可用。** 抽样握手只能排除死地址。协议级握手要真实内核，属 P5。
3. **抽样 24 个的统计误差。** 283 条抽 24 个，±10 个百分点是正常波动；
   `watch` 的本质是"值得再看一眼"，不是"确定能用"。
4. **`proxy-providers` 未跟随。** 发布"带远程 provider 的配置"的仓库无法入库；
   本轮 17 个只有 `xiaoji235` 属此类（其 providers 实为规则集），影响可控。

## 8. 复现

```bash
python3 screen.py                 # 审核内置 17 个候选 + data/candidates.json 队列
python3 screen.py <url> ...       # 临时审某个地址
python3 discover.py --dry-run     # 只看发现了什么，不落盘
python3 discover.py               # 写候选队列（不改订阅）
python3 collector.py              # 按 sources.yaml 采集并重建页面
```
