# P27 深度敏感审计与 UI 真实验收报告

第二轮审计问题 7（真机/暗色/对比度/触控）与问题 8（深度敏感审计）的整改与验收。

## 一、深度敏感审计（问题 8）

原 `audit_privacy.py` 只扫明文 URI/token 正则。本轮增强 `audit_privacy.py`：

| 增强 | 实现 | selftest |
|---|---|---|
| Base64 解码 | 长 b64 片段（≥40 字符）解码后再扫 URI/凭据/token，只接受可打印占比 ≥90% 的结果 | ✔ 命中 Base64 解码后的节点 URI |
| URL query 值 | 新增 `QUERY_SECRET_RE` 扫 `?token=/?sub=/?key=` 等参数值 | ✔ 命中 query 里的 token |
| git 全历史 | `--git` 显式开启，`git log --all -p` 扫真令牌（离线、需 .git） | 实跑：干净 |
| Actions 日志 | `--log <路径>` 显式指定；**日志不在仓库里，不默认扫、不冒充已扫** | 报告如实说明 |

真实结果：
```
python3 audit_privacy.py --selftest   → 9 项全过
python3 audit_privacy.py --git        → 扫描 21 个公开产物（含 Base64 解码 / URL 参数）
                                        git 全历史令牌检查：干净
                                        结论：未发现凭据/令牌泄漏 → 允许发布
```

注入测试：注入 `vmess://eyJ2...` 到 `data/nodes.json` → 命中并拦下（退出码 1），恢复后放行。

**无法验证项**：Actions 运行日志在 GitHub 侧、不在仓库，本沙箱无法取得真实日志内容；提供 `--log` 参数供 CI 落盘后扫描，本地不冒充"已扫日志"。

## 二、UI 真实验收（问题 7）

用 agent-browser（真实 Chromium）在 390px 视口实测，对比度按 WCAG 公式计算（正确合成半透明背景 alpha 后取前景/背景相对亮度比）。

### 文字对比度（WCAG AA：普通文本 ≥4.5:1）

| 元素 | 浅色 | 暗色 | 达标 |
|---|---|---|---|
| body 正文 | 14.59 | 16.45 | ✔ |
| 卡片文字 | 10.94 | 12.59 | ✔ |
| 搜索框 | 17.01 | 17.01 | ✔ |
| 筛选按钮 | 10.94 | 11.24 | ✔ |
| 折叠条 summary | 17.01 | 15.47 | ✔ |
| **小标题 .sec-tag** | **3.53（修复前）→ 5.18** | **3.76（修复前）→ 5.57** | ✔ 修复后 |

**发现并修复的真实缺陷**：`.sec-tag` 是 12.5px/500 字重的普通小文本，用 `--accent` (#007AFF/#0A84FF) 压在淡蓝底上只有 3.5:1，不满足 WCAG AA 4.5:1。新增 `--accent-ink` token（浅 #0A5FD0 / 暗 #5FA8FF），延续项目"语义色文字用深一档"的既有惯例，仅用于 `.sec-tag`，实测修复后 5.18/5.57。改 `template.html` 后经 `collector.py --render` 生成 `index.html`，重新标记 render 阶段并重生成 manifest。

### 触控区（目标 ≥44px）

| 元素 | 修复前 | 修复后 |
|---|---|---|
| 搜索/两个下拉/两个筛选开关/折叠条 | 44 | 44 ✔ |
| **卡片复制按钮 .cbtn** | **42 → 44** | ✔ |
| **卡片二维码按钮 .qbtn** | **42 → 44** | ✔ |

`.cbtn` 注释写"44px 胶囊"但实现是 42px，属注释与实现不符；本轮按 44px 修正。
