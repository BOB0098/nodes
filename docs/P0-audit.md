## 1. 结论摘要

现有项目是一个**单文件采集器 + 静态页**，工程完成度高（零依赖、模板与逻辑分离、自带 QR 编码器），
但**方法论层面与 2.0 目标存在结构性差距**，不是改几个参数能解决的：

| # | 结论 | 严重度 |
|---|---|---|
| 1 | 单一来源贡献 **80%** 节点，前 3 个源占 **97%** | 高 |
| 2 | **Clash YAML / sing-box JSON 源 100% 未入库**：anaer(2,169) + Barabama(2,050) 贡献 0 条 | 高 |
| 3 | 去重键是 `host:port`，实测丢弃了 **1926 条不同配置**的节点（占样本 40%） | 高 |
| 4 | 地区分类 **88% 落到「其他」**，因为靠节点名猜，不是真实出口 IP | 高 |
| 5 | 「可连」= TCP 握手，**不等于代理可用**；82 条 UDP 协议节点从未被检测 | 高 |
| 6 | **公开仓库托管了 3544 条完整凭据**（明文 1.1 MB + base64 1.5 MB） | 高·安全 |
| 7 | 没有节点级数据模型，没有 SQLite/历史，无法支撑评分与淘汰 | 中 |
| 8 | 采集无下载体积上限、无任务锁（Actions 侧有 concurrency） | 中 |
| 9 | 仓库无 LICENSE，集成开源项目前合规缺口 | 中 |

**一句话**：当前系统的定位是「订阅索引」，2.0 要的是「节点质量管理平台」。后者需要把
**检测粒度从「源级抽样」下沉到「节点级实测」**，这是整个改造的主线。

## 2. 当前架构

```
GitHub Actions（cron 17 */3 * * *，带 2h 新鲜度闸门）
        │
        └─► collector.py（单文件，721 行，仅标准库）
                 ├─ collect()       拉 9 个源的原始订阅 → 过滤 → 按 host:port 去重
                 ├─ measure()       逐源统计真实条数 + 抽 24 个节点做 TCP 握手
                 ├─ probe_sources() 逐源 HTTP 探活
                 ├─ probe_meta()    GitHub commits API 取源最后提交时间
                 ├─ update_health() 累计连续低连通轮次 + 内容指纹
                 └─ build_html()    内嵌数据渲染 index.html + 写 nodes.json/status.json
                        │
                        └─► git commit → GitHub Pages（main 根目录）
```

**页面侧**：`index.html` 为构建产物，数据整份内嵌，运行时零网络请求；14 张卡片 3 组，
支持可连率/国内直连两个筛选、复制、二维码弹窗、明暗跟随。

**关键观察：页面清单（`GROUPS`，14 条）与采集清单（`SOURCES`，9 条）是两份互不对应的清单。**

- 14 张卡片里有 **7 张不参与节点库**（尔毛子 clash 全量/可连、radarhub clash、radarhub sing-box、
  bzfq21、awesome-vpn、Andrejewild）——页面显示它们的条数与可连率，但这些节点从未进入 `nodes.json`。
- 反过来有 **2 个源被采集却不展示**（`radarhub/v2ray.txt`、`zhuhaiuk/free-nodes`）。
- 更严重：`collect()` 只保留含 `://` 的行，**Clash YAML 与 sing-box JSON 里的节点全部被过滤掉**。
  结果是两个卡片量最大的源——anaer（2,169 条）与 Barabama（2,050 条）——**对节点库贡献 0 条**。

因此所谓「3,544 条节点库」实际构成是：**84% 来自单一 URI 格式源 ALIILAPRO，0 条来自 YAML/JSON 源**。
这不是「解析器不够强」，是**管线结构性丢失**——占页面 62% 体量的节点从未被纳入管理。

## 5. 检测准确性评估（核心缺口）

| 任务书要求 | 当前实现 | 差距 |
|---|---|---|
| 协议握手 | 无 | 只做 TCP `connect()`，不握手、不认证 |
| 通过代理访问 HTTP 测试地址 | 无 | — |
| 延迟 / 下载测速 | 无 | — |
| 出口 IP / 地区 / ASN / ISP | 无 | 地区靠节点名猜 |
| UDP 协议适配检测 | 直接跳过 | 82 条节点零检测 |
| 节点级结果 | **源级抽样** | 每源只测 24 个，其余 3,520 条无任何实测数据 |

**这是 2.0 与现状最本质的差距**：现在回答的是「这 24 个地址端口通不通」，
任务书要的是「这 3,544 个节点里，哪些真能翻出去、延迟多少、出口在哪」。

### 5.1 实测：去重键过粗的证据

对 ALIILAPRO 源实时样本（4,854 条，经 jsDelivr 获取）用当前 `addr_key()` 口径分析：

| 指标 | 数值 |
|---|---|
| 原始条目 | 4,854 |
| 唯一 `host:port` | 2,928 |
| 同地址含多条目的地址组 | 901 |
| 当前逻辑会丢弃的条目 | **1,926（40%）** |
| 若改用全参数 SHA-256 指纹 | 可保留全部 4,854 |

结论：**当前去重把「同一服务器同一端口、但 UUID/密码/TLS/传输参数不同」的不同节点判为重复**。
任务书 §6 要求指纹覆盖协议、地址、端口、认证、加密、TLS/SNI、Reality、Transport、Flow、UDP，
正是为了避免这类误杀。这一项直接压低「独立有效节点数」——而 2.0 的核心指标正是它。

### 5.2 其他检测层缺陷

- `fetch()` 无下载体积上限（`urlopen(...).read()` 不限长度），存在超大下载/内存风险。
- TCP 探测 64 并发、3s 超时，单轮最多 336 次连接，**无全局预算与熔断**。
- 源级 `count` 与库内归属数**口径不同**（如 ALIILAPRO 卡片 4,854 条 vs 库内 2,835 条），
  页面未解释差异，用户会误以为库里有 4,854 条可用节点。

## 6. 格式兼容性

| 格式 | 解析支持 | 入库 | 输出支持 |
|---|---|---|---|
| Clash / Mihomo YAML | 仅数 `proxies` 条目数，**不解析字段** | **0 条**（被 `://` 过滤掉） | 无 |
| sing-box JSON | 仅数 `outbounds` 条目数，**不解析字段** | **0 条**（同上） | 无 |
| V2Ray URI（明文） | `addr_key()` 提取 host:port | 全部来自这类 | 无 |
| Base64 订阅 | 整体解码后按行处理 | 同明文 | 有（全量导出） |

即：**当前没有任何真正的解析器**，只有「数数」。且因为 `collect()` 的 `://` 过滤，

> **入库率 = 0% for YAML/JSON 源。** 页面统计口径与节点库口径彻底脱节：
> 页面说 Barabama 有 2,050 条，库里 0 条；页面说 ALIILAPRO 4,854 条，库里 2,835 条。
> 两个数字都不是「可用节点数」，用户无从判断。

任务书 §6 要求的标准化、指纹、字段级校验、异常隔离区、协议覆盖（含 AnyTLS、Reality、Flow 等）全部缺失。
P1/P5 需靠集成 Sub-Store / mihomo / sing-box 来补，而不是自己写。

## 8. 安全风险

| 风险 | 现状 | 影响 |
|---|---|---|
| **凭据公开托管** | `订阅 全部节点 明文.txt`（1,113 KB）+ `base64.txt`（1,485 KB），共 3,544 条完整配置，含 **546 个 UUID**、**28 条 password/id 字段**，永久留在公开仓库 78 次提交历史中 | 违反任务书 §6「日志和公开数据不得泄露 UUID、密码」、§13「不泄露凭据」；且与页面免责声明「不生产节点」自相矛盾 |
| 下载无上限 | `fetch()` 不限制响应长度 | 恶意/异常源可撑爆 runner 内存 |
| SSRF 面 | 源 URL 为硬编码清单，用户不可注入 | 当前可控，但 2.0 引入自动发现后必须加白名单与协议限制 |
| 日志 | `print(url[:60])` 截断输出 | 低风险，2.0 需统一脱敏 |
| 许可证 | 仓库无 LICENSE | 集成第三方项目的数据/代码时合规不明 |

> 凭据问题需要**单独决策**：清理现有文件只能删掉工作区副本，**历史提交里的 3,544 条凭据仍在**。
> 彻底处理需重写历史（`git filter-repo`）或把仓库转为私有后再脱敏发布。这一步会破坏
> 现有 Pages 与所有人已保存的订阅链接，属于任务书 §13 明列的「破坏正式环境」操作，
> **已暂停，等待你确认**。

| 验收项 | 现状 | 结论 |
